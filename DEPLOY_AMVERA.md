# Деплой The Runish на Amvera

Один процесс на одно ядро: web обслуживает сайт **и** крутит бота/напоминания/истечение
подписок/GetState-подстраховку в той же горутине (флаг `RUN_WORKER=1`). Отдельный воркер
поднимать не нужно.

> ⚠️ При `RUN_WORKER=1` нельзя масштабировать web больше **1 реплики** — иначе задвоится
> поллинг Telegram-бота и напоминания.

---

## 0. Что уже подготовлено в репозитории

- `Dockerfile` — мультистейдж: собирает фронт (Vite) и два Go-бинарника, web слушает `:8080`.
- `amvera.yml` — сборка из Dockerfile, `containerPort: 8080`.
- `docker-compose.yml` — секреты только через `${VAR}` (для локалки берутся из `.env`).
- `.env` — **в `.gitignore`**, в репозиторий не попадает.
- `.env.example` — шаблон без значений.

Секретов в коммитах нет. Все ключи задаются переменными окружения в кабинете Amvera.

---

## 1. Создать управляемый PostgreSQL

1. Amvera → создать проект → тип **«База данных» → PostgreSQL 16**.
2. После создания скопировать параметры подключения (host, port, db, user, password).
3. Собрать строку и сохранить — пригодится для `DATABASE_URL`:
   ```
   postgres://USER:PASSWORD@HOST:PORT/DBNAME?sslmode=require
   ```
   (у managed-БД обычно требуется `sslmode=require`, не `disable`).

Миграции применять руками не нужно — web прогоняет их при старте (`store.Migrate`).

---

## 2. Создать приложение из репозитория

1. Amvera → создать проект → тип **«Приложение»**.
2. Источник кода: подключить Git-репозиторий (GitHub) или загрузить через Amvera Git.
3. Тип сборки: **Docker** (Amvera подхватит `Dockerfile` / `amvera.yml`).
4. Тариф: **1 ядро** (этого достаточно — web + встроенный воркер в одном процессе).

---

## 3. Заполнить переменные окружения (вкладка «Переменные»)

«Переменные» = env, «Секреты» = скрытые после сохранения. Минимальный набор:

| Ключ                  | Тип     | Значение                                            |
|-----------------------|---------|-----------------------------------------------------|
| `DATABASE_URL`        | env     | строка из шага 1 (`...sslmode=require`)             |
| `BASE_URL`            | env     | `https://<проект>.amvera.io` (или свой домен)        |
| `RUN_WORKER`          | env     | `1`                                                 |
| `PAYMENT_PROVIDER`    | env     | `tbank`                                              |
| `TBANK_TERMINAL_KEY`  | env     | ключ терминала                                       |
| `TBANK_PASSWORD`      | секрет  | пароль терминала                                     |
| `TBANK_API_BASE`      | env     | `https://securepay.tinkoff.ru/v2`                   |
| `BOT_TOKEN`           | секрет  | токен Telegram-бота                                  |
| `BOT_USERNAME`        | env     | username бота (без `@`)                              |
| `ADMIN_TOKEN`         | секрет  | админ-токен                                          |
| `ADMIN_LOGIN`         | env     | логин админки                                        |
| `ADMIN_PASSWORD`      | секрет  | пароль админки                                       |

Необязательные (есть дефолты в `config.go`): `HTTP_ADDR=:8080`, `SESSION_TTL=720h`,
`TBANK_TAXATION`, `TBANK_TAX`, `TBANK_PAYMENT_OBJECT`, `TBANK_PAYMENT_METHOD`, `LOG_LEVEL`.

> `POSTGRES_PASSWORD` нужен только для локального docker-compose — на Amvera БД отдельная,
> в приложение его задавать не надо.

---

## 4. Задеплоить

1. Запустить сборку (push в подключённый репозиторий или кнопка «Собрать/Пересобрать»).
2. Дождаться, пока web поднимется. В логах должно быть:
   - `migrations applied`
   - `embedded worker started (RUN_WORKER=1)`
   - `server starting addr=:8080`
3. Открыть `https://<проект>.amvera.io` — сайт работает.

---

## 5. После деплоя

- **Домен.** По умолчанию `*.amvera.io` с авто-HTTPS. Свой домен подключается в настройках
  проекта (DNS-записи у регистратора + авто-SSL), отдельной платы за домен нет.
  После смены домена обнови `BASE_URL` и пересобери.
- **T-Bank webhook / Success URL.** В кабинете T-Bank указать боевой `BASE_URL`
  (`https://<домен>/...`) — иначе уведомления об оплате не дойдут.
- **Telegram-бот.** Polling сам снимает webhook при старте (`DeleteWebhook`). Если бот
  «молчит» — проверь, что задан `BOT_TOKEN` и web поднялся без падений.
- **Смена секрета.** Env читается один раз при старте процесса → после правки переменной
  перезапусти/пересобери приложение.

---

## Откат на раздельный режим (если когда-нибудь понадобится)

Убрать `RUN_WORKER` (или поставить пусто) и поднять `cmd/worker` отдельным приложением
с тем же набором переменных (кроме `RUN_WORKER`). Тогда web держит только лёгкую
GetState-подстраховку, а полный воркер — отдельный процесс. На одном ядре это не нужно.
